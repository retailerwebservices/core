ADR-002 · Cloud capability amendment

Add secrets management to jimmutable-cloud

Introduce an application-facing secrets port backed by AWS Secrets Manager so AdRocket and other consumers can remove API keys from source code while preserving the environment-selected adapter architecture recorded in ADR-001.

Status: Accepted and implemented Recorded: 2026-07-15 Amends: ADR-001 cloud runtime AWS SDK: 2.31.55 Target runtime: Java 17
Contents Decision Context Architectural delta Service contract Runtime wiring Security boundary AdRocket migration Consequences Verification Evidence

Decision

Add ISecrets as the seventh jimmutable-cloud service port. Application code addresses secrets through four string-oriented operations: create, read, update, and remove. AWSSecretsManager adapts those operations to AWS Secrets Manager using AWS Java SDK 2. Typed failures distinguish rejected mutations, indeterminate mutations, and failed reads. SecretsStub supplies deterministic, in-memory behavior for the STUB environment and unit tests.

CloudExecutionEnvironment remains the composition root. DEV, INTEGRATION, STAGING, and PRODUCTION receive the AWS adapter; STUB receives the in-memory adapter. Consumers obtain the port through getSimpleSecretsService() and do not depend directly on AWS request or response types.

Context and drivers

AdRocket depends on jimmutable-core and jimmutable-cloud, but currently has API keys embedded in its codebase. Source-controlled credentials create avoidable disclosure, rotation, audit, and environment-separation risks. The existing cloud module already isolates storage, search, messaging, email, and cache providers behind interfaces; secret retrieval belongs at the same boundary.

  • Remove credentials from source: applications store only a stable secret identifier.
  • Preserve dependency direction: AdRocket depends on ISecrets, not AWS SDK models.
  • Support rotation and operations: creation, reading, updating, and removal are available through one cohesive port.
  • Keep tests offline: AWS client injection and an in-memory stub avoid network access in unit tests.
  • Follow existing runtime conventions: selection remains centralized in CloudExecutionEnvironment.

Service contract

ISecrets operationAWS requestResult semantics
createSecret(name, value[, token])CreateSecretRequestReturns normally only for confirmed success. Creation accepts an AWS-compatible name, not an ARN. A caller-retained token makes retry intent explicit.
readSecret(id, default)GetSecretValueRequestCurrent string value; the caller-supplied default only when the secret is absent or has no string value. Other provider failures throw SecretReadException.
updateSecret(id, value[, token])PutSecretValueRequestReturns normally only for confirmed success. Reusing the same token and value is idempotent; reusing the token with different data is rejected. SecretMutationException reports REJECTED or UNKNOWN.
removeSecret(id)DeleteSecretRequestReturns normally when AWS confirms deletion was scheduled. The request keeps the AWS recovery policy; failures distinguish rejected from indeterminate outcomes.

Creation accepts a provider-supported secret name. Existing-secret operations accept a name or provider-specific identifier such as an AWS ARN. Shared validation enforces AWS-compatible name characters and bounds, identifier bounds, non-empty values up to the AWS byte limit, and valid request-token syntax. The port intentionally supports string secrets because the initial consumer requirement is API-key storage.

STUBSecretsStubNo AWS client or network access; values exist only in process memory.

The default adapter delegates both credentials and region selection to the AWS SDK provider chains, so deployment configuration such as AWS_REGION is honored. A constructor accepting SecretsManagerClient permits an explicit region, endpoint, credential source, or test substitute without changing the port. The adapter owns clients it creates and closes them through the composition root's JVM shutdown hook; injected clients remain caller-owned.

Security and operational boundary

Values stay out of explicit logs

The adapter does not log secret operations or values. Applications may log sanitized typed failures according to their telemetry policy, but must not add the secret identifier or returned value.

Use workload identity

Production should authorize the process with an IAM role or equivalent default-chain credential source, not another hardcoded AWS access key.

Grant least privilege

Restrict actions and resources to the application’s secret namespace. Read-only services should not receive create, update, or delete permissions.

Deletion is recoverable

removeSecret schedules deletion without forcing immediate removal, retaining the provider’s recovery behavior.

Recommended IAM split

  • Runtime workloads: secretsmanager:GetSecretValue for only the secrets they consume.
  • Deployment or administrative workflows: create, update, and delete permissions where operationally required.
  • Do not grant wildcard resource access merely because the Java port exposes all lifecycle operations.

AdRocket migration path

  1. Create the API key in AWS Secrets Manager under an agreed environment-specific identifier.
  2. Grant each AdRocket workload read access to that identifier through its runtime IAM role.
  3. Replace the literal with a read through ISecrets.
  4. Fail application startup clearly when a required secret is absent, and surface SecretReadException when AWS cannot authorize or complete the read.
  5. Remove the literal from source and history according to the repository’s credential-remediation process, then rotate the exposed key.
Consumer dependency remains provider-neutral String api_key = CloudExecutionEnvironment.getSimpleCurrent() .getSimpleSecretsService() .readSecret("adrocket/api-key", null);

The migration should treat any previously committed key as compromised and rotate it; moving the same value to Secrets Manager does not invalidate copies already present in repository history.

Consequences and trade-offs

Benefits

  • AdRocket can eliminate hardcoded API keys without importing AWS SDK types.
  • Secret storage, versioning, IAM authorization, auditing, and recovery are delegated to AWS Secrets Manager.
  • Constructor injection isolates AWS mechanics and supports request-level unit tests.
  • The in-memory stub fails closed while a secret is pending deletion and conservatively keeps its name unavailable because AWS does not guarantee when asynchronous purge finishes after the recovery window.

Costs and risks

  • Application startup and secret reads now depend on AWS availability, credentials, region configuration, and IAM policy.
  • Callers must handle typed read and mutation failures; an UNKNOWN create or update outcome requires retrying the same value with the same operation token or reconciling provider state.
  • DEV and INTEGRATION use real AWS Secrets Manager unless a caller directly constructs or injects another ISecrets implementation.
  • Adding the service module increases the cloud artifact’s already broad dependency surface.

Alternatives considered

AlternativeReason not selected
Read environment variables directly in AdRocketRemoves source literals but duplicates lookup and lifecycle behavior in every consumer and does not provide managed creation, update, deletion, or recovery.
Expose SecretsManagerClient to applicationsCouples AdRocket to AWS models and weakens substitution, testability, and dependency inversion.
Store keys in S3 or the existing storage portConflates object storage with secret management and lacks a secrets-specific authorization and operational boundary.
Add a general configuration frameworkBroader than the immediate credential-removal need and would introduce a separate configuration lifecycle decision.

Verification and acceptance

  • Focused tests: 15 tests cover request mapping, name validation, fail-closed reads, typed mutation outcomes, idempotent retry tokens, provider-chain region selection, client ownership, deletion policy, and the stub lifecycle.
  • Regression suite: 164 tests completed with 0 failures and 0 errors.
  • Build: Java 17 compilation succeeds with AWS Secrets Manager SDK 2.31.55.
  • Source hygiene: git diff --check reports no whitespace errors.

This ADR records the implemented architecture. It does not claim that AdRocket’s existing literals have already been migrated or rotated.
